# Changelog

## Unreleased

- **Naming correction — `@restormel/aaif` → `@restormel/dispatch` (A2A Phase 0):** the in-house, in-process model-execution envelope is renamed from `@restormel/aaif` (the "Agent-to-Agent Interaction Format / AAIF") to **`@restormel/dispatch`** (`v0.0.19 → v0.1.0`). The acronym collided with the **Agentic AI Foundation** and implied a wire protocol the envelope never was; "A2A" is now reserved for the future spec-conformant Agent2Agent peer (REC-ADR-007). All 32 breaking public identifiers renamed `AAIF* → Dispatch*` (23 types + `executeAAIFRequest`/`isAAIF*`/`ExecuteAAIFOptions`/`AAIFGenerateOutput`); the non-prefixed exports (`INTEGRATION_*`, `RESTORMEL_SUITE_TOOL_NAMES`, the verified-context helpers) keep their names. **No silent break:** every old `AAIF*` name is re-exported from `packages/dispatch/src/deprecated.ts` as a `@deprecated` alias through the pre-1.0 grace period (removed at 1.0). Error code `invalid_aaif_request → invalid_dispatch_request`. Consumers updated in lockstep: `@restormel/connect-core` (`ports.ts`, `ingest/plan.ts`), `@restormel/mcp` (`suite-tool-names.ts`, `routing-capabilities.ts`), dashboard (`integration-catalog-for-flags`, `public-npm-packages`, `EcosystemStrip.svelte`, `StackSetupWizard.svelte`, `memory-inbox.test.ts`), the 3 `workspace:*` dep keys, and root + dashboard build scripts. Dashboard UI/docs prose relabelled "AAIF" → "Dispatch" where it denotes the envelope. **Deferred (gated):** the `integrations/aaif`, `phase-4-aaif`, and `dev-tools/aaif` route directories keep their URLs in this PR (route renames need redirects + nav/sitemap and are a separate follow-on); the `aaif:` MCP `capabilities` output key and the `docs/decisions/aaif-envelope-placement.md` filename are unchanged. Verified: `pnpm --filter @restormel/dispatch` build + 90 tests green; connect-core (173) / mcp (68) / affected dashboard unit tests green.
- **Context-regression CI gate (Stage 2.3):** new composite action `@restormel/connect-eval-github-action` (follows the testing-github-action pattern) runs `keys connect eval --baseline` in CI — remote (gateway key) or local counts mode — posts/updates **one** sticky marker-keyed PR comment with the regression diff table, and fails on the 0/1/2/3 exit contract (warn mode never downgrades config errors). Dogfooded warn-mode on Connect-pipeline PRs against the philosophy-starter fixture (`.github/workflows/connect-eval-gate.yml` + the **`.forgejo/workflows` variant** — the mirror overrides `.github`). Claims integrity: `.github/workflows/connect-efficacy-weekly.yml` re-runs the Stage 1.0a verifier-efficacy benchmark weekly under cross-model routing (`OPENAI_API_KEY` + `TOGETHER_API_KEY` secrets) and fails if any signed-off bar regresses (`scripts/ci/check-efficacy-bars.mjs`, dated snapshot artifact per run); ledger rows 6/8 now point at the workflows. Docs: `/keys/docs/guides/context-regression-ci` (nav, search, sitemap).
- **AAIF hygiene milestone (Stage 5B):** `@restormel/aaif` (zero runtime deps) is now the **single source of truth** for `RESTORMEL_SUITE_TOOL_NAMES` / `RestormelSuiteToolName` / `getEnabledSuiteToolNames`; `@restormel/mcp` re-exports them (new `@restormel/aaif` dependency — no circular deps). Added thorough `isAAIFResponse` unit tests (valid/invalid/edge cases). Refreshed `INTEGRATIONS-FULL-SPEC.md` §8 to the current AAIF types (`routingContext`, `routingPlan`, `integrationStack`, response `embedding`/`outputText`). Recorded a **provisional** ADR ([docs/decisions/aaif-envelope-placement.md](docs/decisions/aaif-envelope-placement.md)) recommending a dedicated AAIF route over `/api/suite/invoke` — decision only, no A2A implementation, pending review.
- **Weaviate graph store adapter (Stage 5A):** `WeaviateAdapter` (`@restormel/graphrag-core`) implements the `GraphStoreAdapter` interface for Weaviate — native vector + BM25 hybrid search, application-layer traversal with a hard `maxTraversalDepth: 2` (clamped requests surface a `GraphSubgraph.warnings` advisory), eventual-consistency writes batched with retry, and `discoverSchema`. Registered in `AdapterFactory` (`type: 'weaviate'`). The Connect pipeline graph-store selector promotes **Weaviate** from "coming soon" to a full option (REST endpoint + API key + collection prefix), persisted in `workspaces.graph_store_config` with a `/v1/.well-known/ready` connection test. Tested against an in-memory fake + a gated live suite (`RESTORMEL_TEST_WEAVIATE_URL`).
- **Verification rule set v1 (Stage 4C):** the implicit six-dimension reasoning-quality scoring is now an explicit, versioned `VerificationRuleSet` (`@restormel/contracts/verification-rules`). Built-in **"Restormel Core v1"** encodes the real weights (logical_structure 0.25, evidence_grounding 0.2, counterargument_coverage 0.2, scope_calibration 0.15, assumption_transparency 0.1, internal_consistency 0.1) with strict/balanced/lenient policies; exported from `@restormel/graphrag-core` with `resolveVerificationRuleSet` / `classifyByPolicy`. Domain packs can override via `verification_rules` (inline weights or a referenced rule set id). New `GET /connect/v1/verification-rules[/built-in]`, `keys rules show|list`, and a developer README. Gateway changelog `1.8.0`. Foundation for the community rule-set registry.
- **`keys replay` CLI (Stage 4D):** `keys replay <traceId | traceFile>` re-runs a past Connect retrieval against the current graph with the same verification policy, depth, and token budget, then diffs the results into **stable / changed (or removed) / new** claims. `--diff` (full per-claim breakdown), `--compare` (original vs current side by side), `--output json|pretty|markdown`. Emits a drift warning when >50% of original claims changed; falls back to a locally saved trace file when a trace is past its 90-day retention. Builds on Stage 4B (`@restormel/contracts/provenance-trace`).
- **Provenance audit trace export (Stage 4B):** every `POST /connect/v1/retrieve` and `/connect/v1/graph` query now stores a versioned `ProvenanceTrace` (`@restormel/contracts/provenance-trace`, `schema_version 1.0`) and returns its `trace_id`. New `GET /connect/v1/traces/{traceId}` and `…/export?format=json` endpoints (Gateway-key/session auth, workspace-scoped, 404 on cross-tenant). Postgres migration `054_connect_provenance_traces.sql` (90-day retention). Dashboard Proof panel surfaces an **Export trace** link for the most recent graph-grounded query. Zuplo routes + `ProvenanceTrace` schema (gateway changelog `1.7.0`). Docs: "Provenance traces" section in the Connect API reference. Foundation for `restormel replay`.
- **Admin user management:** User list reads from app `users` mirror (Neon Auth session upserts) with optional Better Auth `"user"` enrichment — fixes empty table on Neon Auth deployments.
- **Connect ingest quality (admin):** Manual threshold evaluate/apply loop at `/keys/admin/ingest-quality` — replaces GitHub Actions weekly workflow; bumps builtin `prompt_template_version` in Postgres (G2-gated). Migration `049_knowledge_ingest_quality_runs.sql`.
