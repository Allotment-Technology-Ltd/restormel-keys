Frame A The learning journey — the ordering model

The fix for the ordering problem: order by value earned, not dependencies owed. Each rung reveals only what it needs and pays off before asking for more. First-run enters at M0; returning users resume at their rung. Ingest-config (sources + models + store) is a recurring loop, not a one-time step — so model choice sits at ingest-time, not M3.

Onboarding model

The learning journey

Today the implied order is dependency-first (keys → models → store → ingest → review → publish). That's the overwhelm. Flip it: reveal each dependency only at the wall where it unlocks the next benefit, and give a concrete aha at every rung.

Ingest-config is a loop, not a milestone

Sources + models + store are chosen together every time you ingest — first at M1, again on any re-ingest. That's why model choice lives at ingest-time, never after. M3 swaps the store (your DB) and binds your keys; change a model later and it simply applies to your next ingest.
