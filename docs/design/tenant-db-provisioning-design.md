## 0. Consolidated PLAN (phased)

A provider-abstracted per-workspace database design with **EU-sovereign self-hosted as the DEFAULT
tier** and **Neon as a labelled non-sovereign quick-start tier**. One lifecycle state machine
(provision / suspend / delete, keyed on `workspace_id`) drives both providers behind the
`graph-target-service` seam.

**Recommended tenancy model:** per-tenant **DATABASE** with a scoped non-superuser role inside ONE
shared sovereign CNPG cluster (`pg-restormel`). Rationale: catalog-level isolation + clean
`DROP DATABASE` erasure **without a PV per tenant** — the only model that respects the **16-volume
hard cap** on the single cx43 node. Per-tenant *clusters* (own PVs) are reserved for a gated premium
SKU only; schema-per-tenant is rejected (worse isolation at the same density).

### Phase 0 — Logical MVP (today)
Default + quick-start ride shared row-scoped Postgres (REC-ADR-008). Ship only the **tenancy-model
abstraction** so call sites are provider/model-agnostic. **Only phase required before GA.**

### Phase 1 — Per-tenant physical provisioning (sovereign, the Stage-2 deliverable)
Promote a workspace from shared rows to its own `db_ws_<id>` + scoped role on `pg-restormel`, via an
**idempotent, fail-closed** provisioning controller:
- Declarative CNPG `Database`/managed-role; password generated by the controller → Infisical → ESO
  `ExternalSecret` → cluster Secret → CNPG `ALTER ROLE`. **Never** superuser creds in the SvelteKit app.
- Role is `NOSUPERUSER NOCREATEDB NOCREATEROLE`; `REVOKE CONNECT … FROM PUBLIC`; `REVOKE ALL ON
  SCHEMA public FROM PUBLIC` then grant the tenant role only.
- Every step a guarded upsert (re-run = no-op). On any error the workspace stays on its prior target
  and the graph-target `status` → `error` — the app never exposes a half-provisioned DB.
- Promotion = one-way migrate-and-cutover (copy the workspace's rows out, repoint the graph target).

### Phase 2 — Neon quick-start tier (non-sovereign opt-in, OSS-credit-funded)
One Neon project per workspace, EU `aws-eu-central-1` (Frankfurt) pinned at creation, per-project
quota caps, scale-to-zero. Provision/suspend/delete unified with the Phase-1 state machine. **Gated
on the governance triplet (Section B) being filed and founder sign-off.**

### Phase 3 / deferred — dedicated CNPG `Cluster` SKU
Per-tenant cluster (own PVs) as a premium/compliance SKU. **Blocked** until the estate is multi-node
(single cx43 + 16-PV cap → ~6–7 dedicated tenants TOTAL; single-node loss = total outage; Surreal
has no working backups today).

### Isolation guarantees (Phase 1+)
Separate catalog + `REVOKE CONNECT FROM PUBLIC` + a role that can only connect to its own DB ⇒ no
cross-tenant read by construction (materially stronger than Stage-1's "correct `WHERE`"). RLS as
defence-in-depth on any objects that stay shared (workspace metadata, the graph-target registry).
In-cluster networking only (CNPG `-rw`/`-ro` Services, no public LoadBalancer).

### User access
Default = **dashboard-mediated** (user never holds the DB credential; connection string encrypted at
rest via `credential-crypto` AES-GCM, same path as Surreal secrets). Optional **direct read-only
connect** (`role_ws_<id>_ro`, `GRANT SELECT`-only) as a gated, paid, audited tier feature — new
attack surface, MUST pass `restormel-high-risk-security` before build.

### Lifecycle ↔ Art-17 / Art-20
- **Suspend** = `ALTER ROLE … NOLOGIN` (non-destructive, reversible, fail-closed).
- **Delete / day-0 reset** = `DROP DATABASE` (sovereign) or Neon `DELETE /projects/{id}` — the
  **physical erasure primitive** the logical tier lacks (atomic, provable). Logical tier keeps the
  scoped-`DELETE` set, wrapped in one audited `eraseWorkspace(workspaceId)` transaction.
- **Backup-residue caveat (FLAG):** CNPG Barman backups (fsn1) retain WAL/base for **30 days** — a
  `DROP DATABASE` does not erase the tenant from backups for up to 30 days. DPIA/RoPA must state this
  lag OR a per-tenant logical backup stream is required for true point-of-request erasure. **Founder
  decision needed.**
- **Art-20 export** = per-DB `pg_dump` / Neon project export (clean, complete; tractable only with
  physical isolation).

### Density / capacity envelope
- Model (b) per-tenant DATABASE: **0 new PVs/tenant** → bounded by `max_connections`/RAM on the cx43,
  not the PV cap; ~hundreds of small DBs (connection pooler mandatory past a few dozen active).
- Model (c) per-tenant cluster: **~6–7 tenants TOTAL** before the 16-PV cap. Not at GA.
- **Single-node SPOF is the dominant residual risk** — no availability claim until multi-node +
  Surreal backups fixed.

## A. Tenancy + provisioning architecture (EU-sovereign) — full design

> Source of truth for this section. The full architecture write-up (model comparison table,
> idempotent provisioning controller, isolation guarantees, access issuance/rotation, lifecycle
> state machine, density numbers) is reproduced below.

### A.1 Tenancy model comparison

| Model | Isolation | Per-tenant cost (PV/CPU/mem) | Density on cx43 | Lifecycle / erasure | Verdict |
|---|---|---|---|---|---|
| (a) Shared DB + row scoping | Weakest — one bad `WHERE` = cross-tenant read | ~0 marginal | Effectively unbounded | scoped `DELETE`; noisy-neighbour | **MVP / quick-start spine** |
| (b) Per-tenant DATABASE, shared CNPG cluster | Strong — separate catalog, per-DB role, `REVOKE CONNECT FROM PUBLIC` | 0 extra PV, marginal CPU/mem | High — hundreds/cluster, no new PVs | `DROP DATABASE` (clean) | **RECOMMENDED default** |
| (c) Per-tenant CNPG `Cluster` | Strongest — own pods/PVs/backups | 2+ PVs each | ~6–7 tenants TOTAL before cap | delete `Cluster` CR | **Rejected for default** — premium SKU only |
| (d) Schema-per-tenant | Medium — `search_path`+grants; migration fan-out | ~0 extra PV | High | `DROP SCHEMA CASCADE`; poor backup granularity | **Rejected** — worse than (b) |

### A.2 Provisioning (idempotent, fail-closed)
Do NOT hand-roll `CREATE DATABASE` from SvelteKit (would need superuser creds in the app — high-risk
violation). Declarative-first: tenant DB + role are CNPG-managed objects (`Cluster.spec.managed.roles[]`
+ a `Database` CR, ≥ CNPG 1.24), passwords delivered via ESO (`pg-restormel-app-creds` shape in
`deploy/k3s/cnpg/eso-secret-placeholders.yaml`). A thin provisioning controller (small operator OR an
Argo-synced PostSync Job per tenant, mirroring `pbi-lifecycle-postsync.yaml`) idempotently ensures the
DB, the least-privilege role, the grants/revokes, and runs the graph-schema migration inside that DB.
Secret routing: controller-generated password → Infisical (`infisical-restormel`) → ESO
`ExternalSecret` → `kubernetes.io/basic-auth` Secret; never in git, never in the app's plaintext path.

### A.3 Access issuance + rotation
Mediated (default): dashboard holds the encrypted connection string (`credential-crypto`
`encryptProviderSecret`/`decryptProviderSecret`, AES-GCM, `RESTORMEL_CREDENTIALS_ENCRYPTION_KEY`); all
reads/writes via the server, `connect-readonly-profile.ts` deny-by-default tool gate. Direct connect
(opt-in): scoped read-only role, one-time delivery via dashboard, never logged/plaintext; rotation =
controller regenerates → Infisical → ESO re-render → CNPG `ALTER ROLE` lockstep.

### A.4 Lifecycle state machine
Provision (on promotion; evidence-logged) → Suspend (`NOLOGIN`, reversible) → Delete/day-0 reset
(`DROP DATABASE` + `DROP ROLE` + secret deletion). Backup-residue 30-day lag flagged above.

## C. Cost basis + cost-recovery pricing recommendation

> Figures from `scratchpad/phase1-infra-groundtruth.md` (§3 cost, §4 utilisation) and
> `scratchpad/phase2-infra-recommendations.md` (§2). Read-only survey; no pricing applied. EUR→GBP @0.85;
> USD→EUR @~0.92 (illustrative). Every per-tenant figure is unit-economics, not a billed rate — founder sets
> the list price.

### C.1 The load-bearing driver is the 16-volume cap, not GB
Block storage is trivially cheap (EUR 0.0052/GB/mo). The binding constraint is the **16 CSI-volume
attachment hard cap per node**, already at 16/16. A naïve CNPG-per-workspace (2 PVCs each = data+WAL) caps a
node at **~7 workspaces**, not hundreds. ⇒ the realistic sovereign per-tenant unit is a **database (or
schema/role) inside a SHARED CNPG cluster**, not a dedicated cluster.

### C.2 Cost basis per cx43 node
cx43 node EUR 15.99/mo (8 vCPU/16 GB/160 GB); block volume EUR 0.0052/GB; S3 fsn1 EUR 5.94 flat; BX11 EUR
3.81 flat; egress EUR 0 within 20 TiB/node. Backup amortises to ~EUR 0.10–0.20/tenant/mo until storage fills.

### C.3 Per-workspace cost at three densities
Assumptions: 2 GB typical footprint; bill ~3× (6 GB) = EUR 0.031/wksp/mo storage (noise); compute share =
15.99 ÷ tenants/node; RAM (not CPU) is the ceiling; ops overhead ~EUR 1.50/wksp/mo at low density, falling.

| Density (wksp/node) | Compute EUR/mo | Storage | Backup | Ops | **Total EUR** | **≈GBP** | Under 16-vol cap? |
|---|---:|---:|---:|---:|---:|---:|---|
| 10 (dedicated-CNPG premium) | 1.599 | 0.031 | 0.20 | 1.50 | **≈3.33** | ≈2.83 | **NO — 10 dedicated = 20 vols >16** (max ~7) |
| 50 (shared-CNPG logical) | 0.320 | 0.031 | 0.15 | 0.50 | **≈1.00** | ≈0.85 | Yes (2–4 vols) |
| 200 (shared-CNPG packed) | 0.080 | 0.031 | 0.10 | 0.25 | **≈0.46** | ≈0.39 | Yes on volumes; hits RAM/conn ceiling → needs 2nd node / PgBouncer |

True marginal cost ≈ **EUR 0.50–1.00/mo (GBP ~0.43–0.85)** in the shared-logical regime, dominated by fixed
ops. Dedicated isolation ≈ EUR 3.30/mo AND capped at ~7/node ⇒ premium SKU.

### C.4 When physical per-tenant beats shared-logical
Volume-cap crossover (hard): dedicated-per-tenant viable only to ~7 tenants/node; past that every dedicated
tenant needs a whole new node (stepwise jump). **Physical-per-tenant must not be the default on the current
single-node topology.** Recommended split: default = shared logical (long tail, ~EUR 0.50/mo); graduate to a
**shared-CNPG separate DATABASE** (own DB+role, no new volumes, ~EUR 1/mo) for credential isolation/backup
granularity — **the sweet spot the design ships**; dedicated cluster only as a paid premium, gated on the
capacity work. **FLAG:** marketing "per-workspace database" as *physical* while delivering *shared-cluster
separate-database* is a truth-in-advertising + DPIA concern — state the actual isolation level per tier
(`restormel-high-risk-security`, `restormel-isms-governance`).

### C.5 Cost-recovery pricing — sovereign (default) tier
Recommended: tiered free + flat-paid + per-GB overage above a generous quota.

| Plan | Price | Included | Overage | Margin |
|---|---|---|---|---|
| Free / day-0 | £0 | 1 wksp, shared-logical, ≤1 GB, best-effort backup | — | Loss-leader funnel; capped blast radius; ties to day-0 reset / Art-17 |
| Sovereign Standard | £5–6/wksp/mo | shared-CNPG separate-DB, ≤10 GB, PITR, EU/UK sovereign | £0.50/GB over 10 GB | ~6–10× cost recovery; funds ops/DR/HA |
| Sovereign Isolated (premium) | £25–40/wksp/mo | dedicated CNPG cluster, own PVs, isolated backup, priority restore | bespoke | Covers ~EUR 3.30 cost + scarce 2-of-16 volume slot; gated, not self-serve |

Flat-per-workspace (not pure per-GB) matches the cost shape (fixed node+ops dominates). £5–6 funds the owed
HA/2nd-node/DR work. Do NOT loss-lead the sovereign tier (that's Neon's job). Cost-positive from the first
paying workspace; operational break-even for building the per-DB provisioner ≈ **20–50 active paying
workspaces** — below that, run shared-logical and don't build the provisioner yet.

### C.6 Neon quick-start economics — OSS-credit funnel (~USD 5000/yr ≈ USD 417/mo)
Burn dominated by scale-to-zero; idle workspace ≈ USD 0.30–0.50/mo (storage only), light ≈ USD 2–4, steady
always-on ≈ USD 10–20.

| Avg free workspace cost | Free workspaces sustained (USD 417/mo) |
|---|---|
| USD 0.40 (mostly idle) | ~1000 |
| USD 2 (light) | ~200 |
| USD 4 (light-steady) | ~100 |
| USD 15 (steady always-on) | ~28 |

Credit comfortably funds **hundreds of mostly-idle trial workspaces** (the funnel profile); risk = a handful
of heavy always-on workspaces (28 would exhaust it). Policy: free while credit lasts + aggressive
autosuspend; per-workspace credit cap (e.g. USD 5/mo) → prompt upgrade-to-sovereign or BYO-key; burn dashboard
+ 50/80% alerts; at exhaustion → BYO-key (zero cost to us) or migrate to Sovereign Standard £5; label
non-sovereign at provision time (DPIA + sub-processor — `restormel-isms-governance`).

### C.7 Headline pricing recommendation
- **Sovereign (default)** = cost-recovery with margin: **£5–6/wksp/mo flat + £0.50/GB over 10 GB**, delivered
  as **shared-CNPG separate-database** (true cost ~£0.43–0.85/mo; margin funds HA/DR). Dedicated-cluster
  premium **£25–40/mo** for hard isolation, gated by the 16-vol cap.
- **Neon (quick-start)** = the cheap/free funnel, OSS-credit-funded; ~100–1000 mostly-idle trials via
  scale-to-zero; per-workspace USD 5/mo cap; graduation to sovereign or BYO-key. Non-sovereign, labelled.
- **Do NOT ship dedicated CNPG-per-tenant as the default** — breaks at ~7 tenants on the single-node 16-vol
  cap; waits on the multi-node capacity work.

**Risks flagged:** (1) single-node SPOF + 16-vol cap ⇒ no physical per-tenant default today; (2)
"per-workspace database" wording must match delivered isolation (DPIA / truth-in-advertising); (3) Neon credit
drainable by heavy always-on workspaces — needs per-workspace cap + burn alerting; (4) all USD/Neon rates
illustrative, confirm vs the live Neon for Platforms rate card; (5) Neon currently mis-recorded in
`suppliers.yaml` as decommissioning — reconcile before the tier ships.
