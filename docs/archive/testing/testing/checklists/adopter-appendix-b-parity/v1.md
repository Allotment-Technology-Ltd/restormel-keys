# Appendix B parity checklist — v1.0.0

**Audience:** Adopters certifying that **Restormel Testing** in CI meets a stable, reviewable bar (Plotbudget-class “Appendix B”).

**Sign-off shell:** [adopter-parity-signoff-template.md](../../adopter-parity-signoff-template.md) (parties, scope, signature).

## How to use

1. Copy the **verification** column into your ticket or paste row numbers into the sign-off template.
2. For **deterministic** suites, prefer **observe-only** `success_criteria` (`url_matches`, `text_present`, `dom_signals`, `structured_checks`) over agent or judge steps unless semantics require them — see [writing-good-goals.md](../../writing-good-goals.md).
3. **BYOK / model path** checks live under **A3**: [p1-byok-e2e-checklist.md](../../p1-byok-e2e-checklist.md).

## Checklist

| # | Criterion | What “pass” means | Suggested verification |
|---|-----------|-------------------|------------------------|
| **1** | **Logical refs only** | No raw provider keys or long-lived secrets in git-tracked YAML | `ref:restormel-keys:…` / `env:VAR` / CI secret names only; grep for forbidden patterns in PR |
| **2** | **Fork PR policy** | Workflow matches org risk for untrusted forks | Action `fork_policy` or equivalent doc (`skip` / `require_label` / `sandbox_only`) per [github-action-io-spec.md](../../github-action-io-spec.md) |
| **3** | **Deterministic stability** | Goals that are meant to be stable do not depend on LLM/agent flaking | N consecutive green runs on the same commit or rolling main (record N); deterministic goals use observe-only criteria |
| **4** | **Agent / rubric bounded** | Any `ac_sequence` / `judge_rubric` / agent mission has explicit limits | `max_rounds_per_criterion`, suite/goal timeouts, documented env for Keys |
| **5** | **Artefacts in CI** | Run outputs are retained for audit and triage | `run.json`, `report.json`, `junit.xml` (or Action upload paths) present on each run |
| **6** | **Triage without raw model logs** | Failures are explainable from human-facing summary + report | Spot-check one failed run: reason code + summary sufficient for engineer |
| **7** | **Adapter hooks** | If `adapter_hooks` / shell hooks exist, behaviour is documented | README or runbook: ordering, teardown, no prod guard violations |
| **8** | **Preview / `target_url`** | Non-prod URLs are intentional and documented | How preview deployments feed `target_url` or `base_url` per env |

## Monorepo reference (items 3 + 5)

The **`examples/testing-basic-web`** **`web-critical`** suite is the canonical **deterministic, observe-only** smoke run in [`.github/workflows/ci.yml`](../../../../.github/workflows/ci.yml): static server + `testing validate` + `testing run --suite web-critical`. It uses **fewer goals with richer multi-field `success_criteria`** per goal (same surface area as a longer suite, less navigation churn).
